# Put Aptimizer online — a link you can share

End state: a URL like `https://aptimizer.onrender.com`. Anyone you send it to opens it, creates an account, and works. No install, no code, no dependencies on their side.

This uses **one container** — the React app served by nginx, with the FastAPI backend behind it on `/api`. One service, one URL, same origin, so there is no CORS setup to get wrong and no second service to keep in sync.

Two things to create: a database (free) and the app host (free or $7/month).

---

## Step 1 — Database, 5 minutes

The app needs MongoDB, and it must outlive any container restart, so it cannot live inside the app.

1. Go to **mongodb.com/atlas** and create a free account.
2. Create a cluster — choose **M0 (free, 512 MB)**, region closest to your users (Mumbai for India).
3. **Database Access** → Add New Database User. Username and a generated password. Save the password.
4. **Network Access** → Add IP Address → **Allow access from anywhere** (`0.0.0.0/0`). Render's outbound IPs are not fixed, so a narrower rule will lock the app out.
5. **Connect** → Drivers → copy the connection string. It looks like:

```
mongodb+srv://USERNAME:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
```

Replace `PASSWORD` with the real password. Keep this string — it is Step 2's most important input.

M0 is genuinely free and does not expire. 512 MB holds a lot of projects; the app stores JSON, not files.

---

## Step 2 — Deploy the app, 10 minutes

Your code must be on GitHub. If it is not yet:

```bash
cd D:\Workspace
git remote add origin https://github.com/<you>/aptimizer.git
git add -A && git commit -m "Add deployment configuration"
git push -u origin main
```

Then:

1. Go to **render.com**, sign in with GitHub.
2. **New → Blueprint**, pick the repository. Render reads `render.yaml` and proposes one service called `aptimizer`.
3. It will ask for the four secrets marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `MONGO_URL` | the Atlas string from Step 1 |
   | `ADMIN_EMAIL` | your email — this becomes the first admin account |
   | `ADMIN_PASSWORD` | a password you choose; change it after first sign-in |
   | `GEMINI_API_KEY` | from aistudio.google.com — needed for APT and the AI reports |

   `JWT_SECRET` is generated by Render. Do not set it yourself.

4. **Apply**. First build takes 8–12 minutes, mostly npm install and pip install.
5. When it goes green, Render shows your URL. Open it, sign in with the admin email and password, and confirm a project loads.

**That URL is the link you share.** People open it, click Register, and start working.

### Free vs paid on Render

The `starter` plan in `render.yaml` is **$7/month** and stays awake. The **free** plan works identically but sleeps after 15 minutes of inactivity, so the first visitor after a quiet spell waits ~50 seconds for a cold start — fine for testing, poor for anyone you are trying to impress. To use free instead, change `plan: starter` to `plan: free` in `render.yaml`.

---

## Step 3 — Your own domain, optional

In Render: **Settings → Custom Domains → Add**, enter `aptimizer.yourdomain.com`, then add the CNAME record Render shows you at your registrar. HTTPS provisions itself within a few minutes.

## Running the same image on your MacBook

The container is not Render-specific. With Docker Desktop installed:

```bash
docker build -t aptimizer .
docker run -p 8080:8080 \
  -e MONGO_URL="<your Atlas string>" \
  -e DB_NAME=aptimizer \
  -e JWT_SECRET="$(openssl rand -hex 32)" \
  -e ADMIN_EMAIL=you@example.com \
  -e ADMIN_PASSWORD=changeme \
  -e GEMINI_API_KEY=<key> \
  aptimizer
```

Then open `http://localhost:8080`. Same image, same behaviour as production — which is the point of building it this way.

## Updating what people see

```bash
git push
```

Render rebuilds and swaps the container automatically. The database is untouched, so nobody loses work. Roll back from Render's dashboard, which keeps previous deploys.

## Before you send the link to anyone

- **Change the admin password** after your first sign-in, then delete `ADMIN_PASSWORD` from Render's environment — it is only read on first boot.
- **Registration is open to anyone with the link.** There is no invite gate and no email verification, so treat the URL as semi-private until you add one. If it leaks, anyone can create an account.
- **Turn on Atlas backups.** M0 has no automatic backups; take a periodic `mongodump`, and restore one once to prove it works.
- **Watch the AI spend.** Every APT message and AI report is a paid call against your key, made by whoever is using the app — not just you. Set a billing alert, and cap usage before sharing the link widely.
- **The reports are design assistance, not certification.** Anyone acting on them needs a licensed engineer's sign-off. Say so in the product, not only inside APT's replies.

## What this is not

Single-tenant: one deployment, everyone shares one space subject to the existing project-sharing rules. Right for you, your team, or one firm.

Selling access to multiple firms needs per-organisation data isolation, signup and billing, LLM usage caps per tenant, an admin console, and a legal review of how IS/NBC clause content is stored. That is weeks of work, not an afternoon — do not skip it by pointing paying customers at this deployment.
